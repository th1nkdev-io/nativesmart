# Governance

Nativesmart should be managed as a product infrastructure system, not a loose component folder.

## Ownership Areas

- Tokens
- Core logic
- React Native package
- Flutter package
- Kits
- Starters
- CLI
- Documentation
- Release and distribution

## Component Review

Before adding or promoting a component:

- confirm product need
- confirm token usage
- confirm platform idiom
- confirm accessibility baseline
- confirm docs and examples
- confirm no client-specific logic

## Stability Labels

- `experimental`: safe to change
- `preview`: usable but API may change
- `stable`: production-ready
- `deprecated`: replacement exists

## Compatibility

Track supported versions for:

- React Native
- Expo
- Flutter
- Dart
- Node.js
- pnpm
